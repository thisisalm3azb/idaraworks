# The IdaraWorks Pilot Lab

Five fictional companies, several years of coherent operating history each,
living in the **isolated test project only** — so you can try anything, break
anything, and never touch a real customer.

```
Open Pilot Lab  →  choose company  →  choose role  →  open workspace
```

```bash
npm run lab:open                          # lists every company and persona
npm run lab:open -- tradeline finance     # opens Sadaf Trading as the finance user
```

That command starts IdaraWorks on your machine against the test project (every
product surface switched on; AI, country packs and Spanish switched off), mints
a **one-time sign-in link** for the persona, and opens it in your browser. No
password exists for any lab login. The link dies on first use; run the command
again for another.

## What is in the lab, and how it was made

The lab is generated by `tooling/pilot-lab/` — a deterministic, resumable,
idempotent seeder. Its rules are in `tooling/pilot-lab/families/README.md`; the
short version:

- **Test project only.** Every tool loads `.env.test.local` explicitly and
  refuses to run unless every connection resolves to the isolated project. There
  is no override.
- **Marked.** Each company carries an `app_settings` marker `h33.pilot_lab`.
  Nothing without that marker is ever written to or deleted.
- **Deterministic.** Every row's id is derived from (seed version, company,
  family, ordinal). Running the seed twice changes nothing.
- **Legal states.** Where the database enforces a state machine (journals are
  born as drafts and posted; stock is append-only and cites its source; pay runs
  move through review and approval), the seeder drives the product's own
  services or database functions. Bulk rows are inserted only in born states.
- **Reconciled.** After seeding, `npm run lab:verify` recomputes totals,
  balances, ledgers and cross-links and prints every check.
- **Budgeted.** The seeder stops if the database passes 300 MB (60 % of the
  free tier). See `docs/H33-TRUTH-MAP.md` for the budget and why.

Exact record counts per company and module are in `docs/H33-DATA-MANIFEST.md`,
generated from the seed's own manifest.

## Commands

| Command | What it does | Writes? |
| --- | --- | --- |
| `npm run lab:open` | List companies and personas / open one | no (mints a link) |
| `npm run lab:status` | What exists and which families are checkpointed | no |
| `npm run lab:dry-run` | Projected rows and bytes per family | no |
| `npm run lab:seed` | Provision and seed (resumable; idempotent) | test project only |
| `npm run lab:verify` | Every family's reconciliation checks | no |
| `npm run lab:perf` | Time the important surfaces with a real browser | no |
| `npm run test:lab` | The adversarial tenant-isolation sweep | no |
| `npm run lab:residue-check` | Prove production holds none of it (read-only, production) | no |
| `npx tsx tooling/pilot-lab/report.ts` | Regenerate the data manifest from the seed's own numbers | no |
| `npx tsx tooling/pilot-lab/reset-family.ts <co> <family>` | Undo one half-applied family so it can be re-run | test project only |
| `npm run lab:cleanup-preview` | What a cleanup WOULD delete | no |
| `npx tsx tooling/pilot-lab/cleanup.ts --confirm=<phrase>` | Delete exactly the five companies | test project only |

The cleanup phrase names the test project; the preview prints it. The cleanup
refuses if it finds more or fewer than the five marked companies.

## Recreating or removing the lab

- **Recreate after a schema change:** run the seed again. Checkpointed families
  are skipped; new ones run. To rebuild from scratch, clean up first.
- **Remove:** `lab:cleanup-preview`, read it, then run the confirm command.
  Everything created is removed, including the nine logins per company.
- **The lab is deliberately left in place at the end of H33** for manual
  acceptance testing. It is not residue: it is marked, listed in the manifest,
  and removable in one command. Production holds none of it — proved separately.

## What the lab does not do

- It never sends email, SMS, webhooks, or payment requests.
- It never calls an AI provider or a tax authority; those surfaces show their
  disabled / fail-closed states.
- It never touches production. The guard makes that structural.
